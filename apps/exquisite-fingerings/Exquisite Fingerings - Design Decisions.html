Five moves to make it suite-native

It works, and it already pulls the suite's colour tokens — but it's the app that drifted furthest: a bespoke hex renderer, ~490 lines of its own component CSS, a sidebar unlike any sibling, no theme toggle, and no square-grid view. The trigger was a user reaching for the ▦ / ⬡ switch every other grid has, and finding nothing. This commits the redesign — five gaps, each closed by adopting something the suite already shipped.

Source DESIGN_HANDOFF.md Parity targets ProgGenie inspector · Chord Dictionary Primary device iPad Pro · also desktop & web System paper & ink · @enkerli/ui

One principle: adopt, don't reinvent

Every gap here is the same shape — this app hand-rolled something the suite later standardized. The fix is never new design; it's deleting the bespoke version and adopting the shared one: createPitchGrid for the grid, components.css for the chrome, ProgGenie's labelled-card IA for the controls, theme.js for the toggle. What must survive untouched: the Exquis pad geometry & chromatic colours, fingering capture & scoring, pattern save/load, and the MIDI/SysEx path to hardware. Those are the reason the app exists.

G1

The square ⇄ hex switch

Commit · the headline

The bespoke svg-grid.js renders hex only. The rest of the suite moved to createPitchGrid, which already does both layouts from one isomorphic spec. Adopt it — the square view isn't new work, it's a parameter we're not yet passing.

Commit — retire svg-grid.js, render through createPitchGrid

The shared component already exposes layout: "square" | "hex", highlight / highlight2 for chord-vs-scale, labels: note/pc/midi, and an onTap hook. The fingering overlay (finger badges, ergonomic scoring, hand) is the genuinely unique layer and stays — it renders over the shared grid keyed by MIDI note. Result: a square view appears, hex stays pixel-identical to the hardware, and three apps share one battle-tested renderer instead of one app maintaining a fork.

G2

Delete the bespoke CSS

Commit

~490 lines of hand-rolled component styles — sidebar, collapsibles, info/warning/success/error boxes, score display, pattern & issue lists. Almost all of it has a shared equivalent. Map each onto components.css and the file mostly disappears.

Commit — keep only what's genuinely this app's

After the swap, the app-specific stylesheet shrinks to two things that exist nowhere else: the Exquis grid (now mostly createPitchGrid + a thin skin) and the fingering overlay (finger badges, hand colours, ergonomic-score visualization). Everything structural — panels, buttons, controls, sections, eyebrows, numbers, bars, badges — comes from the shared layer. Less to maintain, and visual drift from the family stops at the source.

Commit — group by what the user is doing, fold depth inline

  • One chord/scale source. Capture and Manual both set the harmony today; merge them into a single Chord & scale card. "Custom pitch classes" is just its advanced expander — same card, disclosed on demand.
  • Kill the "Advanced:" prefix. Depth belongs inside the card it deepens (a ▸ advanced expander), not as standalone sections. Geometric suggestion lives under Fingering; it's how you get a fingering, not a separate mode.
  • Layout joins output. The new ▦/⬡ switch, labels, and MIDI I/O are all "how it's shown / where it's sent" — one Grid & output card. Six sections become four, each answering one question.

Cards use the shared .es-section / .es-eyebrow from G2, so this reads identically to ProgGenie's control column — the IA and the styling land together.

G4

Finish dark mode, on purpose

Commit

Every sibling has a ● Dark / ☀︎ Light control; this app relies on OS preference only, and the /* Dark mode (future) */ comment is stale. Dark already mostly works because the tokens carry a dark palette — but the pieces that were hand-rolled (G2) were never QA'd in dark.

Commit — adopt theme.js, audit the hand-rolled remnants

Drop in the standard toggle (it sets data-theme and persists to localStorage; tokens do the rest). Then run the dark audit on exactly the bits G2 replaces — once those use --es-* tokens they inherit the QA'd dark palette automatically. The pads keep their fixed chromatic colours by design (the dark token block already swaps in the brighter --es-pc-* originals that hold ≥3:1 on dark surfaces), so the Exquis grid needs no special-casing.

G5

Layout ≠ orientation

Commit

Today "Portrait / Landscape" (a hex rotation) sits in Display Options. The moment G1 adds a real ▦ / ⬡ layout switch, "Portrait/Landscape" reads as a second layout choice and the two collide. Separate the concepts by naming and by scope.

Commit — one primary layout switch, orientation as a dependent option

Reserve the word Layout for square/hex (matching Chord Dictionary's ◯ ▦ ⬡ language). Rename the rotation to Orientation: ▭ Wide / ▯ Tall and gate it behind hex. Net effect: the control the user went hunting for is now the prominent one, and the setting that used to look like a layout choice is clearly subordinate to it.

Sequencing. G1 (shared grid) unlocks G5's naming and feeds G3's "Grid & output" card; G2 (shared components) is the precondition for G4's dark audit. A clean order: G2 → G1 → G3 → G5 → G4. None of it touches capture, scoring, pattern save/load, or the SysEx path — those ride through unchanged.
